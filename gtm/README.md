# GTM・GA4 の設定

`container-import.json` を GTM に読み込むと、記事の計測に必要なタグ・トリガー・変数がまとめて入る。

## 1. GA4 を作る

1. Google アナリティクスで「プロパティ」を作る（タイムゾーン：日本、通貨：円）
2. 「データストリーム」→「ウェブ」で `https://yuearmy.github.io` を登録
3. 表示される **測定ID（`G-` で始まる）** を控える
4. 「データの保持」を **14か月** に変える（初期は2か月。前の回と比べられなくなるため）

## 2. GTM を作って、読み込む

1. タグマネージャーで「コンテナ」を作る（ターゲット：ウェブ）。**コンテナID（`GTM-` で始まる）** を控える
2. 管理 → 「コンテナをインポート」→ `container-import.json` を選ぶ
   - ワークスペース：既存（Default Workspace）
   - オプション：**統合**（上書きではなく）
3. 変数 →「GA4 測定ID」に `G-WCRNSXP3C0` が入っているか確認する（インポート用ファイルに入れてある。GA4 を作り直したときは書き換える）
4. 右上の「プレビュー」で `https://yuearmy.github.io/how-to-use-AI/` を開き、記事をスクロールしてイベントが出るか確かめる
   - 計測は本番のURLでしか動かない（手元・スマホ確認では送らない作り）。PR #2 をマージして、`public/analytics.js` の `GTM_ID` を入れてから確かめる
5. 「公開」

入っているもの：

| 種類 | 名前 | 中身 |
|---|---|---|
| タグ | Google タグ（GA4） | 全ページで GA4 を読み込む（ページ閲覧も自動で記録） |
| タグ | GA4 イベント - 記事のイベント | 下のイベントを、同じ名前で GA4 に送る |
| トリガー | CE - 記事のイベント | `section_view` `section_pass` `section_dwell` `article_complete` `article_copy` `prompt_copy` `survey_submit` `survey_choice` `survey_comment` |
| 変数 | DLV - section_id ほか | イベントと一緒に送る値（`section_id` `section_title` `seconds` `sections` `survey_id` `choice_id` `choice_count` `item_id`） |

## 3. GA4 でカスタム定義を登録する

GA4 の管理 →「カスタム定義」。登録しないと、レポートで節ごと・選択肢ごとに分けて見られない。

| 種類 | 名前（表示用） | イベントパラメータ | 範囲・単位 |
|---|---|---|---|
| カスタムディメンション | セクションID | `section_id` | イベント |
| カスタムディメンション | セクション見出し | `section_title` | イベント |
| カスタムディメンション | アンケートID | `survey_id` | イベント |
| カスタムディメンション | 選んだ選択肢 | `choice_id` | イベント |
| カスタムディメンション | クリックした要素 | `item_id` | イベント |
| カスタム指標 | 滞在秒数 | `seconds` | 秒 |
| カスタム指標 | 選んだ数 | `choice_count` | 標準 |

- 登録した日より前のデータには反映されないので、**公開前に登録する**
- イベントがレポートに出るまで、最大で1〜2日かかる

## 4. 見るとき

- 「探索」→「ファネルデータ探索」などで、`section_view` をセクションIDごとに並べると、どこで人数が減っているかが分かる
- 掲示板から来た人は、キャンペーン `column_03`（回ごとに変える）で分けられる

## 5. 自分のアクセスを除外する（内部トラフィック）

運営側のアクセスを、GA4 のレポートから除外する。IP アドレスでは分けない（読者も社内の同じネットワークから見るため、読者まで消えてしまう）。代わりに、**ブラウザごとの目印**で分ける。

### サイト側（`public/analytics.js`・実装済み）

- 自分のブラウザで、`https://yuearmy.github.io/how-to-use-AI/?internal=1` を一度開くと、そのブラウザに目印が残る
- 目印がある間は、GTM が読み込まれる前に、データレイヤーへ `traffic_type: 'internal'` が入る
- 目印を外すときは、`?internal=0` つきの URL を開く
- PC・スマホなど、使うブラウザごとに1回ずつ必要

### GTM

1. 変数 → ユーザー定義変数 →「新規」→ **データレイヤーの変数**
   - 名前：`DLV - traffic_type` ／ データレイヤーの変数名：`traffic_type`
2. タグ →「Google タグ（GA4）」→ 設定パラメータ →「行を追加」
   - パラメータ名：`traffic_type` ／ 値：`{{DLV - traffic_type}}`
3. プレビューで、目印をつけたブラウザから開き、Google タグのデータに `traffic_type: internal` が入るか確かめる
4. 公開

### GA4

1. 管理 → データの収集と修正 →「データフィルタ」→「フィルタを作成」→ **内部トラフィック**
2. フィルタ名：`自分のアクセス` ／ **`traffic_type` の値：`internal`**
   - 「内部トラフィック」のフィルタは、標準では「トラフィック タイプ」というパラメータ名を見ている。値の `internal` は、そのまま使える
3. フィルタの状態は、最初は **テスト**。レポートで、内部として判定されているか確かめてから、**有効**にする
   - 「有効」にすると、除外されたデータはあとから戻せない
